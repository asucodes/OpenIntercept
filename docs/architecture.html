OpenIntercept Architecture

How the trust boundary works, end to end

Models trust whatever their tools return. OpenIntercept is an OpenCode plugin plus a local sidecar that lets a human sit on that boundary: every matching tool call pauses for a decision before it runs, and again before its result reaches the model. This page walks the full path with the real OpenCode code we hook.

The decision travels back through the same awaited hook. The model never sees the pause; from its side the call simply takes a moment longer and returns a perfectly normal result.

1. The V1 engine target (opencode 1.x)

V1 exposes classic plugin hooks. OpenCode awaits them inline in the tool runner, which is the load-bearing fact: a hook that does not return holds the tool mid-flight, and edits to the arguments or result propagate only through in-place mutation of the hook's objects. 

packages/opencode/src/session/tools.ts (opencode 1.19.4) - hook emission sites
yield* plugin.trigger(
  "tool.execute.before",
  { tool: item.id, sessionID: ctx.sessionID, callID: ctx.callID },
  { args },                          // mutate args in place to rewrite the call
)
const result = yield* item.execute(args, ctx)
const output = { ...result, ... }
yield* plugin.trigger(
  "tool.execute.after",
  { tool: item.id, sessionID: ctx.sessionID, callID: ctx.callID, args },
  { output },                         // mutate output.title/output to replace the result
)

The adapter registers tool.execute.before and tool.execute.after, POSTs the call to the sidecar, and awaits the decision. Drop means throw a plain tool-failure error; the transcript stays clean of any operator marker.

2. The V2 engine target (opencode 2.x)

V2 changed the shapes and added a wrapper API. Events are typed records, and tool.transform lets a plugin replace a tool's execute function entirely, which is how a spoof can skip the real tool while keeping the original arguments untouched. 

packages/core/src/tool.ts (opencode 2.1.4) - event emission
const beforeExecute = (name: string, input: unknown, context: Tool.Context) =>
  hooks.trigger("tool", "execute.before", {
    tool: name,
    sessionID: context.sessionID,
    agent: context.agent,
    messageID: context.messageID,
    id: context.id,
    input,                             // replace/args edits must mutate this object
  })

packages/core/test/plugin/module.test.ts (opencode 2.1.4) - tool.transform wrapper
yield* ctx.tool.transform(function (editor) {
  editor.add({
    name: "check_tool",
    description: "...",
    execute: () =>
      Effect.as({
        output: { formatted: "..." },
        content: "...",          // what the model sees
      }),
  })
})

OpenIntercept's adapter wraps webfetch and websearch. On a "respond" decision the wrapper returns a fabricated result without invoking the real tool; the hooks path still reports an honest "not executed" original to the local audit log.

3. The wire contract (what crosses the loopback HTTP boundary)

Everything that crosses a process boundary is one zod-validated JSON envelope, shared by adapter and sidecar so a future adapter for another agent only implements the contract. 

packages/protocol/src/index.ts - the essentials
export const Decision = z.object({
  action: z.enum(["run", "replace", "respond", "forward", "drop"]),
  args: z.unknown().optional(),       // replacement arguments (before stage)
  result: ToolResult.optional(),      // replacement or fabricated result
  by: z.enum(["human", "timeout", "auto"]),
  reason: z.string().optional(),
})

export const CallRequest = z.discriminatedUnion("kind", [
  z.object({ kind: z.literal("before"), call: ToolCall }),
  z.object({
    kind: z.literal("after"),
    call: ToolCall,
    result: ToolResult,
    fabricated: z.boolean().optional(),
    spoof: ToolResult.optional(),     // what the model saw when the adapter already replaced it
  }),
])

4. The sidecar (local only, loopback only)

  • Hold queue - each hold is a promise the adapter's HTTP request is blocked on. It resolves on a human decision or a timeout (forward or drop), deduped by callID:stage key so adapter retries reattach instead of double-firing.
  • Rules engine - evaluated top to bottom against tool, stage, args regex, and result regex. First match wins: hold, pass, or drop. Unmatched calls follow the profile default (pass to stay out of the way, or hold for Burp-style operation).
  • Store - in-memory history with per-stage decisions and rule attribution, plus an append-only JSONL audit log as the durable local record.
  • SSE - every state change streams to the panel live: holds, entries, decisions, agent heartbeats.

Every adapter path fails open: sidecar down, timeout, or parse error means the call proceeds untouched. The agent never breaks because OpenIntercept is.

5. Spoofing guarantees (why the model cannot tell)

A spoofed result must satisfy the engine's declared Output schema, otherwise the engine encodes it as a tool failure. OpenIntercept builds engine-aware envelopes: 

packages/core/src/tool/plugin/webfetch.ts (opencode 2.1.4) - declared Output schema
const Output = Schema.Struct({
  url: Schema.String,
  contentType: Schema.String,
  format: Input.fields.format,          // "text" | "markdown" | "html"
  output: Schema.String,
})

packages/schema/src/websearch.ts (opencode 2.1.4) - each result needs a time object
Result({
  url: Schema.String,
  title: Schema.String.optional(),
  content: Schema.String.optional(),
  time: Schema.Object({ published: Schema.Number.optional() }),
})
  • Schema-correct envelopes per engine version - V1 needs {output,title,metadata}, V2 needs the typed structures above
  • Original arguments are never rewritten; the transcript keeps the call exactly as the model emitted it
  • Zero operator markers - no "spoofed" or interceptor strings anywhere the engine or model can observe
  • A real tool failure is never disguised as a success - the error passes through, the local record still shows the intent

6. Lifecycle engineering (the hard-won part)

The OpenCode desktop activates one plugin instance per location in a single process. All mutable state therefore lives in per-registration closures, and registration cleanup deactivates exactly one instance. There is no process-global generation counter - an earlier design where a newer registration superseded older ones silently muted every other location's hooks.

Same-location reloads are handled by the engine's registration scope: the adapter returns a cleanup function that clears its interval and deactivates its own hooks.

7. Deliberate limits

  • No TLS MITM - model traffic is captured at the HTTP client inside the agent's process, before encryption. The plaintext proxy is opt-in, and HTTPS CONNECT is tunnelled, never decrypted.
  • No telemetry - a tool whose job is gating prompts, keys, and tool arguments must have zero egress. The audit log is local and append-only.
  • No active scanning - OpenIntercept observes and gates; it never sends payloads or replays traffic against third parties.
